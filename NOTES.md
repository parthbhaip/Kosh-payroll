## T02 Configuration and profiles (2026-10-05)
- Built: `application.properties` (default profile dev, `ddl-auto=validate`, `open-in-view=false`, gzip incl. SVG from 1 KB, whitelabel off, multipart 5 MB per file / 6 MB per request so a full 5 MB file plus form fields fits), `application-dev.properties` (H2 file `./data/kosh` in MySQL mode, H2 console, `app.mail.transport=log`, seed on, fixed dev-only key), `application-mysql.properties` (DB/SMTP/key/base URL/sender/upload dir from env, SMTP STARTTLS required + auth + 10 s timeouts, `SEED_DEMO` default false), `src/test/resources/application-test.properties` (H2 mem `kosh`, shared across cached contexts via `DB_CLOSE_DELAY=-1`), `.env.example`.
- `com.kosh.config.AppProperties` (record, `@Validated`, picked up by `@ConfigurationPropertiesScan` on `KoshApplication`): `brand`, `zone` (ZoneId), `uploadDir` (Path), `seedDemo`, `dataKey` (+ `dataKeyBytes()`; `toString()` hides it), `baseUrl` (absolute http(s), no trailing slash), `mail.transport` (LOG|SMTP) and `mail.from`. T03 builds the Clock from `zone()` and the AES converter from `dataKeyBytes()`. T08 must pick `LoggingMailService`/`SmtpMailService` by `app.mail.transport`, not by profile.
- Boot 4 gotcha: the whitelabel key is `spring.web.error.whitelabel.enabled`; the old `server.error.whitelabel.enabled` is an error-level deprecation and silently does nothing. Check `META-INF/additional-spring-configuration-metadata.json` in the Boot jars before using any `server.*` key.
- Decision: `spring.devtools.add-properties=false` in `application-mysql.properties`. `spring-boot:run` keeps devtools active, and its 4.1.1 defaults (`spring.web.error.include-stacktrace/-message/-binding-errors=always`, `server.servlet.session.persistent=true`, `spring.mvc.log-resolved-exception=true`) would leak stack traces and rejected PAN/bank values on real data. Devtools reads the flag after the profile files load. Dev keeps the defaults. The mysql profile also sets `spring.devtools.livereload.enabled=false`, because the 4.1.1 LiveReload server binds port 35729 on every interface with no authentication. `ProfileConfigTest.mysqlSwitchesOffDevtoolsPropertyDefaults` checks both flags (devtools is off under JUnit).
- Decision: `mail.smtp.starttls.required=true` next to `starttls.enable` in mysql. `enable` alone falls back to plain text when STARTTLS is missing from the EHLO reply, which an attacker on the path can strip, and that would send `SMTP_PASSWORD` and reset/invite tokens in clear. Port 465 (implicit TLS) is therefore not supported.
- Decision: mysql has no fallback for `APP_BASE_URL` or `MAIL_FROM` (both "Required" in `.env.example`, both in HOW-TO-RUN step 7). With a fallback, a forgotten variable started production that mailed `http://localhost:8080` links from a `.test` sender. Now the unresolved placeholder fails `AppProperties` validation at startup and shows as the rejected value. Only `SEED_DEMO`, `UPLOAD_DIR` and the SMTP host/port/credentials keep defaults.
- Gotcha: the config binder leaves an unresolved `${APP_DATA_KEY}` as literal text, so a missing env var surfaces as the data-key validation error; its message names `APP_DATA_KEY` on purpose. Validation errors print the rejected value, which is why key validity is an `@AssertTrue isDataKeyValid()` (prints `false`) and not a `@Pattern` on the key.
- Every `@SpringBootTest` class carries `@ActiveProfiles("test")`; IDE runners (VS Code, plain JUnit launches) do not import Surefire's system properties and would otherwise fall back to dev's file DB with seed on. Surefire's `spring.profiles.active=test` (pom.xml) stays as a backstop. Tests never use a fixed key: `TestDataKeyEnvironmentPostProcessor` (test sources, registered in `src/test/resources/META-INF/spring.factories` under the Boot 4 key `org.springframework.boot.EnvironmentPostProcessor`) generates one random key per test JVM and adds it with `addFirst`. Relaxed binding maps an exported `APP_DATA_KEY` (and `APP_BASE_URL`) onto `app.*` in every profile, so a key in the developer's shell otherwise outranked the generated one; it still overrides dev's fixed key, as `.env.example` says.
- Tests: `ProfileConfigTest` boots only `AppProperties` per profile with the machine's env vars and system properties removed (no DB opened): default profile, dev and mysql values, missing/blank/short key, mysql without `APP_BASE_URL`/`MAIL_FROM`, an exported `APP_DATA_KEY` under the test profile (`start` takes a fake env-var map), bad base URL, missing transport, `toString`, and `.env.example` covering every `${ENV_VAR}` in the property files (add new env vars there or it fails). `TestProfileTest` (RANDOM_PORT): mem H2 in MySQL mode, generated key, `hbm2ddl.auto=validate`, no OSIV interceptor, no whitelabel `error` bean, multipart limits, and real gzip on `GET /login` - T07's custom login page must stay public and over 1 KB.
